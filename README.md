# نظام الحكيم لإدارة مراكز البصريات — v169

حزمة الإصدار تحتوي ملفات التطبيق اللازمة للنشر على GitHub Pages وتشغيل نسخة PWA.

## الملفات الأساسية

- `index.html` — واجهة النظام والمنطق التشغيلي.
- `sw.js` — Service Worker والتخزين المؤقت دون اتصال. تم تغيير اسم الـ cache إلى v169 حتى لا يعيد المتصفح استخدام ملفات v168 القديمة.
- `manifest.webmanifest` — تعريف التطبيق القابل للتثبيت.
- `offline.html` — صفحة العمل عند تعذر الاتصال.
- `icon-192.png` و`icon-512.png` — أيقونات التطبيق.

## طريقة النشر

1. احتفظ بنسخة احتياطية من ملفات الإصدار الحالي ومن بيانات المركز قبل الاستبدال.
2. فك ضغط الحزمة.
3. ارفع **محتويات المجلد مباشرة** إلى جذر مستودع GitHub Pages، مع استبدال الملفات ذات الأسماء نفسها.
4. انتظر اكتمال النشر، ثم افتح الموقع من المتصفح.
5. على الهاتف: أغلق التطبيق المثبت والمتصفح، ثم افتح رابط الموقع من جديد. إذا بقيت نسخة قديمة، امسح بيانات الموقع/التخزين المؤقت للمتصفح بعد التأكد من وجود نسخة احتياطية محلية، ثم أعد فتح الموقع.

## ما تغير في v169

- جعل دوال الحفظ ترجع نتيجة نجاح/فشل صريحة بدلاً من اعتبار مسار `alert()` نتيجة حفظ.
- لا تُعلَّم جلسة الفاتورة بأنها محفوظة إلا بعد التحقق من قراءة سجل الفاتورة مرة أخرى من التخزين المحلي.
- عند رفض الحفظ بسبب نقص المخزون أو التحقق، لا تُخفى استمارة الفاتورة ولا تُفتح شاشة فاتورة.
- أضيف تحقق بعد كتابة سجل المبيعات وقبل متابعة عرض الفاتورة.
- الإبقاء على عرض الفاتورة داخل التطبيق دون فتح نافذة منبثقة أثناء الحفظ.
- تحديث ذاكرة PWA إلى `hakim-optics-offline-v169-save-verified`.

## تنبيه مهم

هذه مراجعة للكود واختبارات تركيب/صياغة للملفات. لم يتم تنفيذ عملية بيع حقيقية على جهاز المركز أو الاتصال بقاعدة Supabase الحية في هذه البيئة. لا تحذف بيانات الموقع ولا تستورد نسخة قاعدة بيانات تجريبية فوق بيانات المركز. اختبر أولاً على نسخة احتياطية وبعملية تجريبية مناسبة قبل الاستخدام اليومي.
